# Universal Ripper 总结

来源文件：`Universal Ripper.txt`，主题为 C/C++ 中用 char 数组存储中文字符时的内存分配。

## 一、常见编码与单字占用字节数

| 编码         | 一个汉字字节数                 | 说明                        |
| ------------ | ------------------------------ | --------------------------- |
| GBK / GB2312 | 2 字节                         | 例："你" 占 2 字节          |
| UTF-8        | 3 字节（少数特殊字符 4 字节）  | 例："你" = E4 BD A0，3 字节 |
| UTF-16       | 基本汉字 2 字节（扩展 4 字节） | C 里通常用 wchar_t          |

## 二、内存分配原则

假设存储 N 个中文字符：

- **GBK**：`N * 2 + 1` 字节（+1 为结尾 `\0`）
- **UTF-8**：`N * 3 + 1` 字节
- **UTF-16**：`N * 2 + 2` 字节（结尾 `L'\0'`）；用 `wchar_t` 时是 `N + 1`

示例：

```c
char buf[10 * 2 + 1];    // GBK 存 10 个中文字符
char buf[10 * 3 + 1];    // UTF-8 存 10 个中文字符
wchar_t buf[10 + 1];     // wchar_t 本身就是宽字符，按字符数分配
```

## 三、要点

- 用 char 存中文必须**先确定编码方式**。
- 分配内存时按字节数×字符数，并额外留一个结尾符。
- 经常处理中文时推荐 `wchar_t` / `char16_t` / `char32_t`。

## 补充与纠正

1. **wchar_t 大小平台相关**：Windows 上 wchar_t 为 2 字节（UTF-16），Linux/macOS 上为 4 字节（UTF-32）。因此 `wchar_t` 并非跨平台一致的宽字符方案；需要确定宽度时应使用 `char16_t`（UTF-16）或 `char32_t`（UTF-32）。
2. **UTF-8 变长性**：汉字基本区是 3 字节，但扩展 B 区等生僻字（如 𠀀）为 4 字节。若内容包含生僻字，`N * 3` 会不够，建议使用 `std::string` 动态管理，或用 `MultiByteToWideChar`/`mbrtowc` 等按实际字节数计算。
3. **固定长度数组的局限**：上述 `N * 2` / `N * 3` 是上限估算，实际字节数可用 `strlen()` 获取；C++ 场景更推荐 `std::string`（内部按 UTF-8/GBK 字节存储，自动扩容）。
4. **结尾符**：宽字符结尾符是 `L'\0'`，不是 `'\0'`；`wcslen` 与 `strlen` 不可混用。
