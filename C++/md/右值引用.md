右值引用（Rvalue Reference）是 C++11 引入的核心语言特性，语法为 `T&&`。它的本质目的是 **延长临时对象的生命周期，并允许"窃取"其资源**，从而实现移动语义和完美转发。

### 🎯 为什么需要它？

在 C++11 之前，所有表达式要么是左值，要么是右值。右值（临时对象）只能被 `const T&` 绑定，意味着你只能**读**它，不能**修改或转移**它的资源：

```cpp
// C++03: 无法区分"即将销毁的临时对象"和"持久对象"
std::vector<std::string> v;
v.push_back(get_temp_string());  // 必须深拷贝，即使源对象马上就被丢弃
```

右值引用的核心洞察：**如果一个对象马上就要死了，我们不需要复制它，可以直接偷走它的内部资源。**

### 📊 值类别速查

理解右值引用前，必须先厘清 C++ 的值类别体系：

```
            expression
           /          \
      glvalue        rvalue
       /    \          /    \
   lvalue   xvalue   prvalue
              \      /
            generalised lvalue
```

| 类别        | 含义               | 示例                                  | 能被 `T&&` 绑定？ |
| ----------- | ------------------ | ------------------------------------- | :---------------: |
| **lvalue**  | 有身份、可取地址   | `x`, `*p`, `a[0]`                     |        ❌         |
| **xvalue**  | 有身份、但即将过期 | `std::move(x)`, `static_cast<T&&>(x)` |        ✅         |
| **prvalue** | 无身份、纯临时值   | `42`, `get_temp()`, `T{}`             |        ✅         |
| **rvalue**  | xvalue + prvalue   | 以上两者                              |        ✅         |

> ⚠️ **关键陷阱**：右值引用变量本身是左值！
>
> ```cpp
> void foo(std::string&& s) {
>     // s 的类型是 std::string&&（右值引用）
>     // 但 s 这个表达式本身是左值（它有名字、可取地址）
>     bar(s);            // ❌ 调用 bar(const string&)，不是 bar(string&&)
>     bar(std::move(s)); // ✅ 显式转回右值
> }
> ```

### 🔧 两大核心用途

#### 1. 移动语义

```cpp
class Buffer {
    int* data_;
    size_t size_;
public:
    // 移动构造：窃取资源，将源置为空状态
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;   // ← 关键：源对象变为有效但未指定状态
        other.size_ = 0;
    }

    // 移动赋值
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            size_ = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }
};
```

效果：

```cpp
Buffer create();
Buffer b = create();  // 移动构造，零拷贝
```

#### 2. 完美转发

在模板中保留参数的值类别：

```cpp
template<typename T>
void wrapper(T&& arg) {          // 万能引用（forwarding reference）
    inner(std::forward<T>(arg)); // 保持原始的左/右值属性
}
```

这里 `T&&` 不是右值引用，而是 **万能引用**（仅当 `T` 是未推导的模板参数时）。配合引用折叠规则：

| 传入类型       | T 推导为 | T&& 折叠为         | forward 结果 |
| -------------- | -------- | ------------------ | ------------ |
| `int` (右值)   | `int`    | `int&&`            | 右值         |
| `int&` (左值)  | `int&`   | `int& &&` → `int&` | 左值         |
| `int&&` (右值) | `int`    | `int&&`            | 右值         |

### ⚡ 重要规则与陷阱

#### 引用折叠规则

```
T& &   → T&
T& &&  → T&
T&& &  → T&
T&& && → T&&
```

**只要有一个左值引用参与折叠，结果就是左值引用。**

#### 不要对返回值使用 std::move

```cpp
// ❌ 错误：阻止 NRVO/RVO
Buffer foo() {
    Buffer b;
    return std::move(b);  // 强制移动，反而阻止了编译器优化
}

// ✅ 正确：让编译器自动选择 NRVO 或隐式移动
Buffer foo() {
    Buffer b;
    return b;
}
```

#### 移动后的对象状态

移动后的对象处于 **"有效但未指定"** 状态：

- ✅ 可以安全析构
- ✅ 可以重新赋值
- ❌ 不能假设任何特定值
- ❌ 不能调用依赖内部状态的方法（除非文档保证）

#### noexcept 很重要

移动构造/赋值应标记 `noexcept`，否则 STL 容器（如 `std::vector` 扩容）会退回到拷贝以保证强异常安全：

```cpp
// vector 扩容时的决策逻辑（简化）
if constexpr (std::is_nothrow_move_constructible_v<T>)
    move(elements);    // 优先移动
else
    copy(elements);    // 退回拷贝
```

### 🆚 常见混淆辨析

| 概念                         | 说明                                         |
| ---------------------------- | -------------------------------------------- |
| `T&&` 作为函数参数（非模板） | 右值引用，只接受右值                         |
| `T&&` 作为模板参数           | 万能引用，接受一切                           |
| `auto&&`                     | 万能引用                                     |
| `const T&&`                  | 几乎无用，既不能修改也不能移动               |
| `std::move(x)`               | 仅仅是 `static_cast<T&&>(x)`，不移动任何东西 |
| `std::forward<T>(x)`         | 条件性转换，仅在模板中配合万能引用使用       |

> 💡 **一句话总结**：右值引用是一种类型系统级别的"许可证"——它告诉编译器和程序员："这个对象即将消亡，你可以安全地掠夺它的资源"。移动语义利用这张许可证避免不必要的深拷贝，完美转发利用它保持泛型代码中的值类别信息。
